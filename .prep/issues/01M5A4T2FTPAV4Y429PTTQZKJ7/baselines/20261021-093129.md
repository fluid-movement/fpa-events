## Requirement

Found by the authorization audit (01M5A34Y0620NBQFRA09MKZWNN).

**Vulnerability.** The Schedule tab's server load, `src/routes/events/[id]/admin/schedule/+page.server.ts` (the `load` at line 22), has no guard of its own. Its comment says "Access is already guarded by the layout load", relying on `src/routes/events/[id]/admin/+layout.server.ts` (lines 18-25: `requireSignedIn` + `canManageEvent`). SvelteKit does not run a layout's server load on every data request: a `__data.json` request carries `x-sveltekit-invalidated`, and Kit runs only the nodes marked `1` (`render_data` in `node_modules/@sveltejs/kit/src/runtime/server/data/index.js` returns `skip` for the rest without calling them). A client can therefore ask for the leaf alone and the manage-area guard never runs.

**Reproduce (dev server, anonymous, no cookies).** `GET /events/<id>/admin/schedule/__data.json` answers with the layout's redirect to sign-in. The same URL with `?x-sveltekit-invalidated=001` answers `{"nodes":[{"type":"skip"},{"type":"skip"},<leaf>]}`: the leaf load ran for an anonymous caller. Tried on 2026-10-19 against a dev server on its own port; for an existing event the leaf returns the schedule rows and the event's coordinates.

**Impact today.** Low. The rows it returns (sanitized schedule items, event lat/lng) are already public on `/events/[id]`. But (a) for any event without stored coordinates the load makes an outbound geocoding call to Photon, so anyone can make the server call Photon on demand, once per request; and (b) anything later added to this load on the assumption that only managers reach it leaks to everyone. Every other server load under a guarded layout (`settings/profile`, `dashboard`, `attending`, `organizing`, `events/create`) guards itself, so this is the only leaf with the gap.

**Severity:** low. **Blocks go-live:** I do not think it blocks, but the fix is a few lines and I recommend it before go-live so the manage area's guard does not depend on the layout.
