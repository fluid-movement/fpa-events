Use `@sentry/sveltekit` with a GlitchTip DSN (/decisions/01M57G90Y5GDVT34B6CNE6M6XR.md); see /architecture/build-and-deploy.md (Errors in production).

- **Server**: `handleError` in `src/hooks.server.ts` already calls `describeServerError` (`src/lib/server/errors.ts`), which returns null for anything but `kind === 'unknown'` and mints the 8-character `errorId`. Capture the exception after that null check, so only unexpected errors are sent, and pass `errorId` as a tag and the route id (`event.route.id`) as the transaction/route, never `event.url`. Set the user to `{ id }` only. Extend `describeServerError`'s tests if the rules change.
- **Browser**: there is no `src/hooks.client.ts`; add one with `handleError` that inits the SDK and captures unexpected errors, returning the same shape the error page expects.
- **Scrubbing**: `sendDefaultPii: false`; a `beforeSend`/`beforeBreadcrumb` that drops request URLs, query strings, cookies and breadcrumbs, because `/api/calendar/[token]/feed.ics` and `/invite/[token]` carry credentials in the path. Put this in one shared function used by both sides and unit-test it.
- **Config**: declare the DSN in `src/env.ts` (server, private) and a public DSN for the browser, both optional; blank disables the SDK like Mailgun/R2/Turnstile. Leave both out of `.env.test` so dev and Playwright send nothing.
- **CSP**: `svelte-options.js` `connect-src` currently allows only `self` and Photon; add the GlitchTip origin (from the public DSN's host), or the browser SDK is blocked.
- **Source maps**: enable build source maps and upload them to GlitchTip at build time with the Sentry vite plugin/`sentry-cli` pointed at the GlitchTip URL (`SENTRY_URL`, auth token, a release name). Coolify build args carry the token. GlitchTip's handling of SvelteKit maps is unverified: throw a test error on the deployed app and confirm readable frames before closing.
- **Privacy policy**: add a section in `src/routes/privacy-policy/+page.svelte` for the tracker: what an event contains, that it is stored on our own server, and its retention. It is not a third-party processor.
- The GlitchTip service and DSN come from the deploy issue; develop against any Sentry-compatible endpoint.
