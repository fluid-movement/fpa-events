Crews get ONE body text and ONE declared language, edited by crew admins on the crew edit page and shown on the details page (sections already marked by the listing issue). Columns on crews: `body` text (sanitized HTML) and `body_lang` text (BCP 47 tag, nullable when no body); same migration as the banner issue (this run implements both).
Edit: use `src/lib/components/RichTextEditor.svelte` (takes the owning form's `fields`, see AGENTS.md) and `sanitizeRichText` from `#lib/utils/html` on the way in; a language select built from a curated list of ~30 common languages with names from `Intl.DisplayNames` (value is the BCP 47 tag; validate server-side against that list). Body required together with language.
Display: render with `src/lib/components/RichContent.svelte` inside an element carrying `lang={bodyLang}`; the surrounding page stays in the app language, user-generated names get `translate="no"`. New `src/lib/translate.ts` pure helpers: `primaryLanguage(tag)`, `shouldOfferTranslation(declared, browserLanguages)` (false when the primary subtags match). New component `TranslatableText.svelte`: when `shouldOfferTranslation` is true AND the Chrome Translator API exists (`'Translator' in self`; feature-detect, use `Translator.availability` then `Translator.create({ sourceLanguage, targetLanguage })`; handle 'unavailable'), show a 'Translate' button that translates the text content of the body (translate the sanitized HTML's text nodes, keeping markup — or translate per block element — never inject translated strings as HTML) with a 'Show original' toggle; on failure fall back to the original and show nothing alarming. Without the API do nothing extra (the lang attribute lets the browser's own translate offer work). `navigator.languages` is the target.
Tests: Vitest for `src/lib/translate.ts` (same language hides it, regional variants, case, empty browser list) and for the language validation; Playwright in `tests/integration/crew-media.test.ts` (shared with the banner issue): admin saves text with a language, details page has the `lang` attribute, sanitization strips script, non-admin cannot edit.
