Authentication audit, 2026-10-19, parent 01M5A34XDWPGKSKMTVA213DHX7.

Vulnerability: an attacker who already holds a session retains account access after the owner resets or changes the password. The recovery flow changes the credential but does not revoke sessions. The app exposes no session-management UI to end all other sessions. This is persistence after credential compromise, not a way to obtain the first session.

Where: src/lib/server/auth.ts:31-40 does not set emailAndPassword.revokeSessionsOnPasswordReset. The installed Better Auth 1.7.7 reset handler (node_modules/better-auth/dist/api/routes/password.mjs:155-170) only deletes sessions when this option is true. src/routes/settings/password/+page.svelte:25-26 calls changePassword without revokeOtherSessions; Better Auth's update-user.mjs:160-186 only revokes/rotates when requested. Sessions otherwise last seven days and renew after one day of activity; get-session does not compare the session with a password-change timestamp.

Reproduction class: in an isolated test with a throwaway identity and two independently authenticated clients, reset the password through a valid reset link, then use the older client's cookie to access a protected page. Repeat with the settings password-change flow. The old session remains valid. The audit used only synthetic fixture objects and adapter spies, with no database writes or accounts created: a successful reset called updatePassword but never deleteUserSessions, and a successful password change called updateAccount but never deleteUserSessions. These observations agree with the source branches above. No live recovery flow was run.

Severity: high because account recovery does not terminate an intruder's existing access (including organizer/admin access if that identity has it). Go-live recommendation: fix before cutover. A stolen session is a prerequisite; this is not an anonymous account takeover.

Fix: enable session revocation on password reset, and have the settings password change revoke other sessions and rotate the current one. Preserve the existing correct-password requirement. Regression tests must prove the old cookies stop authorizing, not merely that a revocation helper was called. This is a security rule under AGENTS.md.
