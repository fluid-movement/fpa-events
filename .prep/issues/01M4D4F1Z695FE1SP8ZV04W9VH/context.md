The root layout `src/routes/+layout.svelte` sets only `<title>FPA Events</title>` in `<svelte:head>`; event pages load their data in `src/routes/events/[id]/+page.server.ts` (event row with `picture`, `picture_width`, `picture_height`, `location`, schedules, start/end dates) and render in `+page.svelte`. Pictures are public R2 URLs (`R2_PUBLIC_URL`, see `src/lib/server/r2.ts`).

Add a small shared component (or helper) in `#lib/components` that renders the meta block, and use it from the layout (site-wide default: description, `og:title`, `og:type` website, `og:url`, `twitter:card`) and from the event page (title, a description built from the dates and place using a named function in `#lib/utils/dates`, per AGENTS.md; strip rich text with `stripHtml` from `#lib/utils/html`, never raw HTML; `og:image` only when the event has a picture, with its width and height when known, `twitter:card` summary_large_image then). `og:url` must be the public origin plus path: use the request URL origin as Kit 3 gives it (see /decisions on Kit 3 and the open request-origin deploy issue); do not read it from a client-only source.

The CSP (`svelte-options.js`) is unaffected: meta tags are not fetched by the page. Link-preview crawlers do not run JS, so the tags must be in the server-rendered HTML. Test: a unit test for the description/escaping logic (an event title or description containing quotes and markup must not break the attribute), and one integration check that a seeded event's HTML contains `og:title` and `og:image` (fetch the HTML, not a browser render).
