description: 'PROPOSAL, not a decision. Note: decision /decisions/01M5A7BXTN2R18VM3V9S0AJPHQ.md was written by the earlier Codex auditor, not by the user; treat it as a draft until the user confirms, amends or supersedes it. Why a rule is needed: there is no CI and no automated advisory alert; the only gates are local git hooks; two independently locked trees exist (root and tools/migrate); the runtime image carries the whole tree (01M5A7WXTDVVKVSFJZ1ETPYF0F); and at audit time 30+ packages were behind, including runtime ones (@sveltejs/kit 3.0.0 vs 3.1.0, better-auth 1.7.8 vs 1.7.11, sanitize-html, marked, svelte, vite, drizzle-orm, @aws-sdk/client-s3). Proposed rule: (1) Turn on GitHub Dependabot security alerts (alerts only, no auto-PRs) for the private repo so advisories arrive without a schedule; this is the cheapest substitute for the missing CI. (2) Monthly, and before any release that changes dependencies or the Node image: run npm audit in the root and in tools/migrate (while it exists) and give every advisory either a fix issue or a recorded acceptance with its reachability reason; take patch and minor updates of runtime dependencies (the dependencies block plus @sveltejs/kit, svelte, vite) with npm update, then the existing pre-commit and pre-push gates. (3) Security-relevant runtime packages (better-auth, @sveltejs/kit, sanitize-html, marked, postgres, @aws-sdk/client-s3) get a fixing release within a week of an advisory that reaches the app; dev-only tooling within the monthly pass. (4) Majors are separate, deliberate issues. (5) After any dependency change, run npm install once locally so node_modules matches the lock before running audits or probes against installed code, and never deploy anything but npm ci from the committed lock. Alternative if the user prefers less process: only (1) plus the pre-release npm audit; the reason that might suffice is that the app''s runtime surface is ~20 packages and current advisories are all dev tooling.'
